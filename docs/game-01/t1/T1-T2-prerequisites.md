# T2 integration prerequisites

T1 does not authorize T2 implementation. These are required follow-up design and verification tasks.

1. **Trusted boundary.** Authenticate ownership before reading any run or receipt. Never accept state snapshots, keys, seed choice or correctness from a client. The pure engine validates commands but deliberately trusts its server-owned state. Validate stored snapshot schema and invariants before hydration; malformed storage is a recovery error. Keep factory/adapter/keys behind a server-only import boundary and verify the actual browser bundle. Only `present` and authorized post-submit feedback may leave that boundary.
2. **Atomic commit.** Persist scoring state, receipt and any future evidence in one transaction/CAS on authoritative revision. Two different operations at one cursor must have one winner; the loser loads the authoritative outcome without grading again. A reducer result is only a proposal until commit. Test 32 simultaneous duplicates, competing tabs, pre/post-commit failures, exhausted retries and crash recovery against the real store. T1's 32 sequential replays do not prove this.
3. **Durable identities.** Scope receipt lookup by owner/run/operation; reject changed fingerprints, retain original immutable response and retain historical runs after restart. Same-operation lookup precedes stale/terminal/content checks, after ownership checks. Specify retention and unique identity allocation. T1's `usedRunIds` grows across its local lifecycle; replace with durable uniqueness/history policy. Add start/restart operation receipts so lost creation responses cannot accidentally create extra runs. Those services are absent in T1.
4. **Draft selection.** T1 selection is ungraded and does not increment scoring revision. Resolve whether draft editing remains local or uses a separate version before storing it; concurrent draft updates must not overwrite committed scoring state. Explicit confirmation sends the exact reviewed choices. Preserve both boss choices in one submission.
5. **Pinned content.** Persist exact manifest digest, item/revision/order, rule version and seed. Load the matching immutable evaluator on resume, not the latest bank. Missing/withdrawn content must return recovery/invalidation without FAILED or run consumption. Archive old receipts independently so replay does not need new content. T1 keeps the last 20 assignment sets for least-recently-seen sampling and excludes each prior run's record on every floor. Approve durable exposure/history policy; a pool of two necessarily repeats after two runs.
6. **C0 learning gates.** Keep all 12 records/14 decisions DRAFT. Independently review bilingual copy, single defensible answers, source exposure and distractors; no educator review has occurred. Mechanical schema tests do not establish CEFR calibration, productive recall or mastery. Preserve source commit and P01–P08 aliases resolving to exact native IDs in C0 provenance; publication needs reviewed hashes and full manifest validation.
7. **Lesson return and UX.** Implement exact original-lesson/version resolver for R-VOC/R-SIGN/R-ASK/R-FOLLOW without changing travel, checkpoint or completion. Before start record acknowledgement of C0 reset/no-loss/no-timer/boss rules. Test select–review–confirm, pending/reconcile, honest per-part failure feedback, missing lesson fallback and keyboard/mobile accessibility. T1 returns logical remediation IDs; no working deep link or UI is claimed.
8. **Economy and modes.** No XP, stamp, reward, travel loss or progression writes. First-clear amount/policy and stamp remain unapproved. Challenge versus future Practice remains the C0 design; no mode toggle, reward service or permanent failure penalty is implemented. Owner approval plus separate isolation/idempotency tests must precede any reward work.

Release remains blocked by these applicable gates, independent educator/adversarial approval, real persistence/concurrency/hosted verification and existing auth/deployment blockers. A successful application build does not resolve them.
